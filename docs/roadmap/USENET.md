# Usenet (SABnzbd) support plan

Status: planned (2026-10-14), checked against `fixes/integration` @ 41838483 (highest migration 0309; this work uses 0320–0324).

## Owner decisions

- **Downloader:** SABnzbd first; NZBGet later through the same client slot.
- **Bundling:** optional, off by default — `install.sh --with-sabnzbd` (a compose profile like Prowlarr) adds a pre-wired SABnzbd; otherwise connect your own in Connections. Users bring their own provider and indexers.
- **Preference:** best release wins regardless of network by default; a setting prefers Usenet or torrents.
- Defaults adopted from the plan (not asked):
  1. Tie-break when equal under "Best wins": indexer priority → download-client order (0148) → stable order.
  2. "Prefer X" decides after score and before size (Sonarr-like); never a hard filter.
  3. Every SABnzbd failure blocklists and fails over, except disk/permission/write errors (Needs-you item). Test warns when SABnzbd's language isn't English (fail messages are translated).
  4. After import: archive the job in SABnzbd history and delete its leftover folder (default on; per-client switch via 0321).
  5. Usenet with no progress never fails over automatically; health warning after 30 min (usually a provider/account problem affecting every job).
  6. Bundled SABnzbd: linuxserver/sabnzbd pinned to 5.1.x, `pp=3`; API key generated by the init container, read from a read-only config mount — never in `.env` or printed.
  7. A user's own SABnzbd: Arrmada creates its categories only when the user clicks "Add missing categories".
  8. Retention filter and NZBGet: not in this pass.

## What exists today

Newznab indexers (`indexer.KindNewznab`, `TransportUsenet`) are hidden while no usenet client exists (`SetUsenetAvailable` is never wired), Prowlarr sync skips usenet indexers, MOV-11 keeps usenet releases from being recommended, and `download.Service.Add` tries every client regardless of transport (a SABnzbd row must never receive a torrent, nor qBittorrent an NZB). The client kind is locked to qBittorrent and "bundled" means a single row.

## Key design

- **Download key, no table rewrites:** `grabs.info_hash`, `imports.download_hash`, `import_reviews.hash` hold a *download key* — torrents keep their lowercase hex hash; usenet uses `sab-<lowercased nzo_id>`. `download/key.go`: `ValidKey` (hex or `^sab-[a-z0-9_]{1,80}$`; never `all`, commas or pipes), `KeyTransport`, `Kind.Transport()`.
- **download package:** `KindSABnzbd`; `Item.Transport/FailMessage/Labels`; `Phase()` gains `unpacking`; `AddDownload(ctx, req) (Added{ClientID, Key})` restricted to clients of `req.Transport` (fail-over stays within a transport; `Add()` stays as the torrent wrapper); commands routed by the snapshot item's `ClientID`; `HasTransport` (cached) feeds `indexer.SetUsenetAvailable` and `grabbable`; bundled clients by kind.
- **Migrations:** 0320 `grabs.transport TEXT NOT NULL DEFAULT 'torrent'`; 0321 `download_clients.options` (JSON: pp, priority, after-import cleanup); 0322 reserved (lifecycle); 0323–0324 spare. Preference is the setting `download_network_preference` = `best|usenet|torrent`.
- **NZB fetch server-side** (`fetchNZBPayload`: validate `<nzb`, cap ~64 MB, Newznab `<error>` → plain message) and `addfile` — the indexer apikey inside NZB URLs never reaches SABnzbd's history or the browser.
- **Usenet never seeds:** `SeedEnabled=false` for usenet grabs (incl. manual uploads); "remove after import" = archive history + delete the job folder inside the mapped downloads root (pathguard).
- **Stall/fail-over:** Failed history → fail-over + blocklist next tick; disk/permission → attention, no blocklist; no progress → health warning only; unpacking holds the stall clock; vanished-from-history handled like vanished torrents.
- **Ranking:** `quality.Candidate.Usenet` — always "alive", MinSeeders doesn't apply, seeders tie-breaks skipped when either side is usenet; a `KeyNetwork` step (v1 after Total; v2 after GroupTier) only when a preference is set; one release per network per title, then preference / indexer priority / client order. v2 stays shadow-only.
- **Adoption:** a key-less usenet grab (lost add response) pairs with the SABnzbd job whose `nzbname` normalises to exactly its title.

## SABnzbd API

`POST {url}/api` form `mode=…&apikey=…&output=json` (key never in URLs/errors; full API key, not the NZB key). Test: `version` → `get_cats` → `fullstatus&skip_dashboard=1`; health reads `get_config` (misc, categories). Add: `addfile` (`nzbfile`, `nzbname`, `cat`, `priority=-100`, `pp=3`, `password` from NZB meta) → `nzo_ids[0]`. Queue: `mode=queue`; history: `mode=history&category=…` (`status`, `fail_message`, `storage`). Remove: queue `name=delete&del_files=1`; history `name=delete` (archives). Pause/resume per job and global; `change_cat`; `retry`. "Hostname verification failed" → plain fix (host_whitelist).

## UI

Connections: kind picker (qBittorrent · SABnzbd), SABnzbd card with categories ✓/✗ + "Add missing categories", completed folder + "Arrmada sees it at …", usenet servers status. "Usenet" chip on release rows, queue rows (no seeds/ratio/reannounce/recheck; MB left · ETA; Retry on failed), History, Blocklist; never on Seeding. Stage "Unpacking". Settings → Downloads `#network`: "When a release is on both Usenet and torrents" (Best release wins · Prefer Usenet · Prefer torrents), shown only with a usenet client. Upload ".torrent or .nzb". Wizard Indexers step: one line on adding SABnzbd + Newznab indexers.

## Testing

Unit tests with recorded SABnzbd 4.5/5.x fixtures; `ValidKey` fuzz; ranking/preference tables; stall/failure classes. Offline end-to-end (`ARRMADA_SABNZBD_IT=1`, `scripts/usenet-it.sh`): pinned linuxserver/sabnzbd 5.1.x + NZBGet's NServ as a fake NNTP provider serving synthetic yEnc articles and generated NZBs (fallback: a small Go NNTP test server in `internal/download/nntptest`) — happy path, missing articles, par2 repair, 7z split + passworded, SABnzbd restart mid-download. Owner checks with a real provider: SSL/563 and connections, retention, real RAR unpack and obfuscated names, indexer API limits, Prowlarr usenet sync, duplicate detection, speed and the disk guard during unpacking.
